# 项目历程：从模型搜索到可部署工具

## 1. 起点：需求并不是“找一个分割模型”

最初的问题是如何让实验室积累的细菌显微图像能够被自动分割、计数并进一步用于单菌形态和荧光定量。现有资料分散在多个目录中，同时包含原图、人工标注、传统算法 mask、展示用图片和重复文件。如果不先确认数据对应关系，任何模型排名都可能建立在错配或错误标签上。

因此，本项目首先把任务拆成三个问题：

1. 哪些原图和掩膜能够可靠配对？
2. 不同模型分别适合什么成像模态和测量目标？
3. 如何把实验结论转化为其他使用者和 Agent 都能稳定调用的工具？

## 2. 数据审计：先验证“答案”是否可信

通过目录扫描、文件匹配和图像质量核对，项目整理出 2,902 对原图–既有处理 mask，并将 576 个无法可靠找到原图的处理文件隔离在主统计之外。

人工/人工候选掩膜共有 15 张。逐张检查后发现，其中 1 张存在空间错位，3 张存在渲染伪影或异常颜色，最终只有 11 张进入准确率评估。这个过程改变了后续工作的重点：评估流水线必须保存配对清单、裁剪坐标和排除原因，而不能只输出一个最终均值。

## 3. 候选模型：通用模型、细菌专用模型和交互式模型

调研选择了三条具有不同假设的技术路线：

- Cellpose-SAM `cpsam_v2`：通用实例分割基线，用于检验跨模态泛化和快速整图覆盖。
- Omnipose `bact_phase` / `bact_fluor`：针对细长、弯曲和密集细菌设计，并按明场/相差与荧光模态分工。
- MicroSAM DeepBacs：显微图像专精模型，同时具备交互修正潜力，适合“自动初分割—人工复核”的流程。

传统图像处理 mask 也被保留下来，但只作为历史流程一致性参照，不作为人工真值。

## 4. 统一实验：让模型差异可解释

所有模型采用统一的 512×512 输入窗口。大图使用中心裁剪，GT 和参考 mask 应用相同裁剪框，避免模型预测和标签不在同一坐标系。最终完成四个模型分支共 8,706 份实例标签。

评估从单一的“分出多少个细胞”扩展为多个维度：

- AP@0.50 / AP@0.75：实例检出与严格重叠；
- IoU / Dice：整体前景覆盖；
- Boundary F1：边界位置；
- 相对计数误差：总体数量；
- split / merge：过分割与粘连结构；
- 面积、长度、宽度和荧光强度误差：分割对后续生物学测量的影响。

这一步揭示了视觉效果、计数和单菌边界并不是同一个目标：一张看起来覆盖完整的结果，仍可能把一个菌体拆成多个实例；总数接近 GT，也可能同时存在 split 和 merge。

## 5. 结论：不是选出唯一赢家，而是建立任务分工

在 11 张可靠荧光 GT 上，Cellpose-SAM 的 AP@0.50、前景 Dice 和中位相对计数误差更好，适合作为覆盖和计数基线。MicroSAM DeepBacs 的 AP@0.75、Boundary F1 以及匹配实例的多数形态/荧光误差更好，更适合强调边界和单菌测量的场景。Omnipose `bact_fluor` 在本批数据中出现较多 merge，需要重点处理密集菌体粘连。

当前没有可靠明场人工 GT，因此明场结果只能用于流程验证和失败模式观察，不能声称真实准确率。最终选型必须随业务目标变化，而不能把这组有限数据上的均值扩展为通用排行榜。

## 6. 工程化：把一次实验变成可复用能力

综合覆盖、计数、通用性、许可证和部署复杂度后，项目选择 Cellpose-SAM 作为首个工程化基线，并进一步构建 [`cellpose-kit`](https://github.com/desperati0n/cellpose-kit)：

- 使用 FastAPI 封装 GPU 模型推理；
- 使用 Docker Compose 固定环境和 GPU 配置；
- 增加健康检查、API Key、文件与参数校验；
- 输出 `uint32` 实例标签、质检预览、逐实例统计和运行元数据；
- 通过 Agent Skill 提交本地图像并解释输出边界。

由此形成了完整闭环：

> 数据审计 → 模型实测 → 指标解释 → 许可证核对 → 技术选型 → 服务部署 → Agent 调用。
