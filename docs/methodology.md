# 评估方法与口径

## 数据角色

| 数据 | 用途 | 是否可以表示真实准确率 |
|---|---|---|
| 通过审计的人工实例掩膜 | 定量 GT | 是，但受当前 11 张荧光样本规模限制 |
| 待复核人工掩膜 | 补标候选 | 否 |
| 传统算法或历史处理 mask | 流程一致性参照 | 否 |
| 无标注明场图像 | 失败模式观察 | 否 |

## 坐标与输入规范

- 当前批量实验统一使用 512×512 输入窗口。
- 大于 512×512 的原图使用中心裁剪，GT 和参考 mask 必须使用相同裁剪框。
- 已经为 512×512 的图像保持原尺寸。
- 小于目标窗口的图片需采用明确且一致的补边策略后再进入评估。
- 实例标签使用整数图：`0` 表示背景，每个正整数表示一个独立实例。

## 核心指标

### 实例匹配

构建 GT×预测实例的 IoU 矩阵，在指定阈值下按 IoU 从高到低执行一对一匹配。

- `AP@0.50 = TP / (TP + FP + FN)`
- `AP@0.75` 使用相同定义，但要求 IoU ≥ 0.75。
- 实例 precision 为 `TP / (TP + FP)`，recall 为 `TP / (TP + FN)`。

### 前景覆盖

将所有非零实例合并为二值前景后计算：

- `IoU = intersection / union`
- `Dice = 2 × intersection / (GT foreground + predicted foreground)`

这两个指标不能区分实例是否被正确拆开。

### 边界

从二值前景提取边界，计算预测边界到 GT 边界、GT 边界到预测边界的距离。在当前默认 2 像素容差内分别得到 boundary precision 和 recall，再计算 Boundary F1。

### split 与 merge

- split：一个 GT 实例与多个预测实例存在显著重叠。
- merge：一个预测实例与多个 GT 实例存在显著重叠。

当前实现将“占预测面积超过 15%，且占 GT 面积超过 10%”视为显著重叠。它是一种失败结构诊断规则，而不是跨论文统一标准；比较其他工作时必须同时报告阈值。

## 限制

1. 可用人工 GT 仅有 11 张，且全部为荧光图像。
2. 模型参数调优和最终测试若使用同一批图，会产生乐观偏差；后续应建立独立留出集。
3. 传统 mask 可能包含系统性误差，因此一致性高不等于真实准确率高。
4. 当前汇总未报告 bootstrap 置信区间，也未覆盖双标注者一致性。
5. 不同成像模态、菌种、密度和显微镜配置可能改变模型相对表现。

公开的指标实现位于 [`src/bacterial_segmentation_benchmark/metrics.py`](../src/bacterial_segmentation_benchmark/metrics.py)。
